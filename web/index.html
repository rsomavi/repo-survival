Most repos die in their first month.
This one predicts which.

Paste a GitHub repository and get a survival estimate based only on signals from its first 30 days — commits, contributors, and how issues were handled.

How the prediction works

  1. 01

    Fetch the first month

    The GitHub API is queried live for commits, contributors, and issues from the repository's first 30 days — nothing more recent is used.

  2. 02

    Compute the same features as training

    Commit frequency, contributor count, issue close ratio, and repo metadata are turned into the exact feature set the model was trained on.

  3. 03

    Predict with a Random Forest

    A model trained on 2,397 repositories returns a probability of activity six months to years later.

Where this breaks

  • Python only. The training sample covers Python repositories created in 2023–2024; other languages or eras may behave differently.
  • Solo, non-social projects score low even when healthy. Personal or academic repos that don't use GitHub Issues or a public license — like a thesis project worked on alone — get flagged as likely abandoned, because those are the same signals unmaintained repos show.
  • Survivorship in the sample itself. Repositories deleted by their owners never entered the training data, so the model has never seen that outcome.
  • "Active" means pushed to recently — not popular, not well-maintained, not finished. A repo with one commit last week counts as active.
